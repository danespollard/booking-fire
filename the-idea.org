* App Idea: Availability Messaging for Musicians (and Similar Niches)

** Core Insight
- The product is not “scheduling” but *availability messaging*.
- For music gigs (and similar work), sending a booking link feels:
  - like extra work for the buyer
  - too corporate for the relationship vibe
- Goal: frictionless, natural, plain-text availability sharing.

** Core Product Promise
- *In 10 seconds, produce a copy/paste message of your openings*
- Output should look natural in:
  - SMS / iMessage
  - Email
  - Facebook Messenger / Instagram DMs

* MVP Workflow

** 1) Availability Input (Musician-First Mental Model)

*** Mode A: Quick Add Openings (Most Common)
- Add dates
- Optional time-of-day labels:
  - “daytime”
  - “evening”
  - “after 9pm”
- Later mark as:
  - hold
  - booked

*** Mode B: Default Pattern + Exceptions
- Example: “Usually free Thu–Sat evenings”
- Block out exceptions:
  - travel days
  - rehearsals
  - booked gigs

** 2) One-Button “Copy Openings” (Templates)

*** Templates Are the Killer Feature
- Editable per user to match personal voice

**** Short + Friendly
- “I’m open: Thu 2/19, Fri 2/20, Sat 2/21 (evenings). Want me to hold one?”

**** More Options
- “Next openings: Thu 2/19 (eve), Fri 2/20 (eve), Sun 2/22 (day).”

**** Grouped by Weekday
- Great for recurring venues
- Example:
  - Thurs: 2/19, 2/26
  - Fri: 2/20, 2/27
  - Sat: 2/21

** 3) Holds (Critical for Real Booking Workflows)

*** Statuses
- Open
- Hold
  - name
  - expiry (e.g., “Hold for The Blue Room until Wed”)
- Booked

*** Optional Export Inclusion
- “Currently on hold: Sat 2/21 (The Blue Room — expires Wed)”

* Why This Wins vs Calendly

- No links to click
- Booker replies directly: “Let’s do Fri.”
- Value proposition:
  - booker-friendly
  - fast
  - preserves relationship vibe

* Rails App Blueprint (Minimal)

** Data Model
- User
- AvailabilityBlock
  - start_at (datetime, with timezone)
  - end_at (datetime)
  - kind: open | hold | booked
  - note (venue name, travel, hold-for info)
  - hold_expires_at (nullable)

- Block-based approach avoids complex rules early
- Recurring logic can be layered on later

** Export Endpoints
- GET /openings.txt
  - params:
    - from
    - to
    - group_by=weekday
    - include_holds=1
    - format=short
- GET /openings.json
  - future-proof for UI + API

** UI
- Month/week calendar
- Click/drag to create blocks
- Keyboard shortcuts:
  - O = open
  - H = hold
  - B = booked
- “Copy” button writes plain text to clipboard
- Hotwire + Stimulus recommended

** Initial Pricing

** Venue Presets
- Examples:
  - Bars/Clubs → evenings only
  - Weddings → weekends + travel buffer
  - Private events → include set-length footer
- Each preset = template + filters

* Market Landscape & Validation

** Existing Solutions
- Calendly-style tools:
  - focus on booking links
- Poll tools:
  - When2Meet, WhenAvailable, Timeful/Schej
  - optimized for group convergence
- Lightweight tools:
  - availability → plain text utilities
  - often ad-hoc or unpolished

** Opportunity
- Space exists for a focused, polished product
- Clear niche + tight workflow is key

* Sellable MVP Definition

** Core “Magic Trick”
1. Mark Open on a calendar
2. Mark Booked / Block out time
3. Click “Copy openings as text”
   - date order OR
   - grouped by weekday

** Differentiators Worth Paying For
- 1-click paste formats:
  - email bullets
  - weekday grouping
  - “next 2 weeks only”
- Recurring rules + exceptions
- Optional private read-only link
- Export to .txt and possibly .ics

* Alternative Rails MVP Sketch

** Models (Minimal)
- User
- AvailabilityWindow (optional)
- OpenDay (date) OR OpenRange (start_date, end_date)
- BookedRange (start_date, end_date)
- (Later) Rule for recurring weekdays

- Prefer ranges; expand to dates at export time

** Export Endpoint
- GET /openings.txt
  - from=YYYY-MM-DD
  - to=YYYY-MM-DD
  - group_by=weekday
- Returns text/plain
- Suitable for copy/paste or API use

** UI
- Month grid
- Click = toggle Open
- Shift + drag = mark Open/Booked range
- “Copy as text” button hitting .txt endpoint
